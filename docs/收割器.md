# 收割器使用说明

本目录之外的 `harvester/` 是收集客户端：它按专题从 OAI-PMH 来源收集成果，并在
本地保留可以互相解释的四类材料。它不依赖来源的管理接口（`/__control`、
`/__log`），也不使用这些接口生成任何采集结果；所有事实都来自
Identify、ListSets、ListMetadataFormats、ListRecords、GetRecord 的响应。

## 快速开始

    python -m pip install -r requirements.txt
    python -m source.server --port 8765          # 终端一：启动合成来源
    python -m harvester initial   --source http://127.0.0.1:8765/oai --set teaching   # 终端二
    python -m harvester update    --source http://127.0.0.1:8765/oai --set teaching
    python -m harvester reconcile --source http://127.0.0.1:8765/oai --set teaching

每次运行都输出一份 JSON 报告（同时写入状态目录的 `reports/`），说明：

* `source`：来源地址、仓库名、协议版本、删除语义、粒度与最早日期；
* `set`：本次覆盖的专题及其名称；
* `formats` 与 `dateRange`：请求的格式、日期范围（双端包含）、增量的水位回退秒数；
* `coverage.confirmed` / `coverage.pending`：已确认范围与待补范围；
* `counts`：请求数、原始响应数与字节数、现行成员与撤消数；
* `runs`：每个格式的页链状态、已观察/已收集标识符数、原始响应 id 列表。

退出码：`0` 表示所有请求格式的页链都完整结束；`1` 表示有页链未完成或格式
不可分发（报告仍会写出）；`2` 表示无法继续的配置或传输错误。

## 三种运行模式

### initial —— 首次建库

对选定专题做全量列举（不设日期上下限），为每个声明的格式分别建立页链、
原文、成员关系和水位。重复执行是幂等的：同一标识符的同一格式只保留一条
现行记录，不会因重叠窗口产生重复成果。

### update —— 继续更新

按 (专题, 格式) 水位做增量列举，日期下界回退 `--overlap-seconds`（默认 5 秒），
覆盖"同一秒内多次更新"的情况；上界默认开放。增量中**没有出现**的旧记录
不会被当作删除，也不会被当作专题移出。

列举范围是整个来源而不是单个专题：撤回是全局事实，且已经移出专题的记录不会
再出现在专题列举里，只有全来源列举才能看到它们的删除头。列举结果按专题归属
过滤后再收集：只保留当前属于该专题、或曾经被记录在该专题中的成果；其他专题
的成果只计入 `listedIdentifiers`，不进入资料库。

### reconcile —— 专题核对

再次全量列举，并逐条核对专题成员：

* 只有能观察该专题的全部格式页链都完整结束，才允许判定移出；否则整次核对
  只输出"待补"，不改变任何成员关系。
* 确认"未出现"的记录只从**这个专题**移出，不影响它在别的专题的归属，也
  不改变它作为成果本身的有效性。
* 如果在核对过程中，另一次完整采集又观察到该记录仍属于本专题，本次不移出，
  记为 `membership-removal-deferred`（待补），而不是硬判。

## 协议事实如何被区分

| 来源信号 | 收割器的理解 | 落盘结果 |
| --- | --- | --- |
| 正常记录 | 成果现行、格式可用 | `record_formats` 保存该格式原文，`current_availability=1` |
| 删除头（`status="deleted"`） | 成果撤回，持久事实 | `tombstones` + 全部已知格式 `available=0`，历史原文继续保留 |
| `noRecordsMatch` | 本次范围无记录 | 运行标记 `completed`，成员关系不动 |
| `cannotDisseminateFormat` | 格式不可分发 | 运行标记 `unsupported`，成员关系与可用性不动 |
| `badResumptionToken` | 续页凭证失效 | 尝试从第一页重起；仍失败则运行标记 `incomplete`，水位与移出不更新 |
| 网络错误 / 5xx | 单次请求失败 | 运行标记 `failed`，不推进水位、不判定移出 |
| 专题中不再出现（全量核对） | 专题移出 | `memberships.state='removed'`，只影响该专题 |

同一次响应里同一标识符在 `oai_dc` 与 `research` 两个格式各有一份原文：
`record_formats` 以 `(identifier, metadataPrefix)` 为主键，两者互不覆盖；
`record_format_history` 记录每次内容变化，`raw_responses` 保存原始字节。

撤回不会留下"仍被当成有效成果的另一格式"：撤回会把该标识符所有已知格式的
可用性一并置为 0，并用 GetRecord 交叉核对其它已声明格式；若另一格式仍返回
正记录，记 `withdrawal-format-conflict` 事件并仍按撤回处理。若撤回之后来源
又给出正记录，只记 `post-withdrawal-present` 矛盾事件，不会复活成果。

## 工作人员视图

    python -m harvester show   --source ... --set teaching            # 专题构成
    python -m harvester show   --source ... --set teaching --record ID # 单条成果的来历
    python -m harvester show   --source ... --set teaching --coverage  # 各格式覆盖状态
    python -m harvester events --source ... --set teaching             # 事件流
    python -m harvester raw 123 --source ... --set teaching --out raw.xml

`show` 把专题成员分成三类，使"专题缩小"可以解释：

* `effective`：现行有效；`formatsMissing` 列出尚未被完整采集覆盖的格式（待补）；
* `removed`：经完整全量核对确认的专题移出（仅此专题）；
* `withdrawn`：来源撤回，附删除头的 datestamp 与原始响应 id。

`pendingCoverage` 汇总未完整结束的运行和延迟的移出判定。`show --record`
逐格式给出当前原文、可用性、历史快照（从原始响应还原当时的标题与 setSpec）、
成员关系历史和涉及的全部原始响应（URL、抓取时间、SHA-256、字节数）。

## 存储结构

状态目录（默认 `./harvest-state/<来源地址转写>`）下：

* `harvest.sqlite3`：全部结构化状态（见 `harvester/store.py` 的 schema）；
* `reports/<jobId>.json`：每次运行的完整报告。

`raw_responses` 只增不改，是解释任何一次采集结论的最终依据。

## 测试

    python -m unittest discover -s tests -t . -v

`tests/test_source.py` 检查来源契约；`tests/test_harvester.py` 用同一合成来源
演练建库、同秒更新、增量的"未出现不等于删除"、专题核对移出、撤回后双格式
失效、凭证过期后的安全重试、重叠窗口不重复，以及"收割器不访问管理接口"。
